# Environment Variables per AI Environment

zsh determines the AI environment via a single environment variable. herdr injects `$HERDR_SESSION` into all panes. Paseo injects `$AGENT_ENV` via provider definitions. zsh loads the corresponding environment variables for that value.

## Load Order

`~/.config/zsh/.zshrc` contains:

```zsh
[[ -r "$XDG_CONFIG_HOME/zsh/agent-environments.zsh" ]] && source "$XDG_CONFIG_HOME/zsh/agent-environments.zsh"
```

`agent-environments.zsh` is a single file generated by chezmoi containing definitions for all environments.
The environment name is resolved in the order `AGENT_ENV` -> `HERDR_SESSION`.
If `$AGENT_ENV` is a defined environment name, it takes precedence over `$HERDR_SESSION`.
If neither is a defined environment name, no environment is loaded. Variables such as `CLAUDE_CONFIG_DIR` will not be set, and `claude` and `codex` will be intercepted by stub functions with the same names. To start an AI CLI specifying an environment, use `agent --provider=<provider-id>`. No warning is emitted at load time.

Paseo does not inject `HERDR_SESSION`. Instead, `agents.providers.<provider>.env.AGENT_ENV` in `~/.paseo/config.json` provides the environment name. This env is written via `jq` by `run_onchange_after_90-agent-envs.sh`.
If the environment is mismatched in Paseo, check the provider's `AGENT_ENV` rather than `HERDR_SESSION`.

## Environment Definitions

Definitions are in `[[data.environments]]` of `~/.config/chezmoi/private-data.toml`.
Because this is outside the git repository, neither environment names nor Cloudflare account IDs enter git.

```toml
[[data.environments]]
    session = "default"
    label   = "P1"
    agents  = ["claude", "codex"]
    cloudflareAccountId = "..."
```

| Field | Meaning |
|---|---|
| `session` | Value taken by `AGENT_ENV` and `HERDR_SESSION`. Also serves as suffix for directory names |
| `label` | Display name shown in SketchyBar's usage widget |
| `agents` | Subset of `["claude", "codex"]` |
| `cloudflareAccountId` | Value of `CLOUDFLARE_ACCOUNT_ID`. Omitted if not exported |

**The first element of the array is primary**, and only the primary uses unsuffixed directories.

| Environment | Claude | Codex | Wrangler |
|---|---|---|---|
| First (primary) | `~/.config/claude` | `~/.config/codex` | `~/.config/.wrangler` |
| Second onward | `~/.config/claude_<session>` | `~/.config/codex_<session>` | `~/.config/.wrangler-<session>` |

The switched variables are `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `WRANGLER_HOME`, `CLOUDFLARE_ACCOUNT_ID`, and `AGENT_ENV_SESSION` / `AGENT_ENV_AGENTS` which convey the resolved result.

Tools not present in `agents` have no environment variables configured and are masked by matching zsh functions. Invoking them prints a warning and exits non-zero, falling back neither to primary nor tool defaults.

## Adding an Environment

1. Add a `[[data.environments]]` block to `~/.config/chezmoi/private-data.toml`.
2. Run `chezmoi init` to regenerate `chezmoi.toml`.
3. `chezmoi apply` is executed by the user. Directories for second and subsequent AI environments are created by `run_onchange_after_90-agent-envs.sh`.
4. Changes take effect in a new shell. Existing open panes will not be affected.

## Migration from Legacy claude_secondary / codex_secondary

The second environment previously occupied fixed-name slots named `~/.config/claude_secondary` and `~/.config/codex_secondary`. When named via `[[data.environments]]`, directory names become `~/.config/claude_<session>`. **Migrate contents before applying.**

```sh
mv ~/.config/claude_secondary ~/.config/claude_<session>
mv ~/.config/codex_secondary  ~/.config/codex_<session>
```

If applied without migrating, the newly named directory is recreated empty, leaving credentials (claude's `.claude.json`, codex's `auth.json`) and history (claude's `projects/`, `todos/`, `history.jsonl`, codex's `sessions/`) stranded in the old slot.
`.chezmoiremove` only removes symlinks deployed by chezmoi (`agents`, `commands`, `skills`, `hooks`, `CLAUDE.md`, `settings.json`, `AGENTS.md`), so runtime state is not lost even if migration is forgotten.

After moving, inspect removal targets with `chezmoi diff` or `chezmoi apply --dry-run --verbose` before applying.

## Notes

- Only values safe for public disclosure may be stored here. Under chezmoi management, this enters git and the repository is public. Environment-specific values (environment names, Cloudflare account IDs, etc.) must reside in `[[data.environments]]` of `~/.config/chezmoi/private-data.toml` and be referenced as loop variables in templates. API tokens belong in neither (see `secrets.md`).
- `$HERDR_SESSION` is also inherited when launched via `claude -p` or `claude --resume`.
- The Alt+C new tab launcher (`~/.config/herdr/launch-claude-tab.sh`) also checks `agents` and exits without creating a tab in environments without claude. The check is performed using `$HERDR_SESSION` rather than `AGENT_ENV_AGENTS`. Key commands of `type = "shell"` start detached on the herdr server and therefore inherit the server environment rather than the focused pane, where the server's `AGENT_ENV_*` reflects the launching shell (primary environment).
- Inspect resolved results via `echo $AGENT_ENV_SESSION`. Check input variables with `echo $AGENT_ENV $HERDR_SESSION`. If `AGENT_ENV_SESSION` is empty, no environment has been loaded.
